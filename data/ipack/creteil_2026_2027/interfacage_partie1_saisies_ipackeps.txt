### Examens : les saisies dans iPackEPS avant Cyclades (document officiel 2026-2027, partie 1)
[PORTEE: gt, pro, cap]
Réponse directe — l'ordre des étapes dans iPackEPS (septembre-octobre) : 1) déclarer certificatives les APSA évaluées aux examens ([Dossiers] / [Dossier EPS] / [APSA]) ; 2) déposer le référentiel d'évaluation de chaque APSA certificative ([Dossiers] / [Dossier Certificatif] / [Dépôt des Référentiels]) ; 3) déclarer les groupes concernés par les examens et leur liste d'APSA ([Dossiers] / [Dossier EPS] / [Groupes], bouton [Gérer les S.A.]) ; 4) placer les élèves dans les groupes s'ils sont séparés de leur classe ([Dossiers] / [Dossier EPS] / [Élèves]) ; 5) configurer les protocoles : dates de rattrapage et co-évaluateur extérieur ([Dossiers] / [Dossier Certificatif] / [Protocoles d'Évaluation]). Puis, à partir de janvier-février : 6) exporter les élèves et leur protocole vers Cyclades ([Dossiers] / [Dossier Certificatif] / [Cyclades]).
Réponse directe — ce qui n'est pas transféré vers Cyclades : une APSA non déclarée certificative ; une APSA dont le référentiel n'a pas été déposé ou a été refusé par la commission académique ; un protocole incomplet ou non conforme. Le contrôle de validité vérifie notamment 3 APSA de 3 champs d'apprentissage différents en bac GT, au moins 2 APSA de la liste nationale et la présence d'un référentiel pour chaque APSA.
Réponse directe — protocole adapté : un groupe peut être déclaré avec un protocole adapté dès sa création ; sa validité n'est alors pas testée (1 à 3 APSA autorisées, pas de contrôle des champs). Il est déclaré conforme dès qu'au moins une APSA est déclarée, sans référentiel à déposer : « Cyclades autorise toute APSAs dès lors qu'elle est déclarée adaptée ».
Avant l'export (janvier-février) : actualiser la liste des élèves dans [Dossiers] / [Dossier EPS] / [Classes] (arrivées, changements de classe, départs) — le document l'attribue encore au coordonnateur, mais depuis la version 2026.2 tout enseignant peut actualiser les classes et les élèves (notes de version de Créteil) ; puis placer dans leur protocole les élèves arrivés en cours d'année ([Dossier EPS] / [Élèves], astuce : [Visualisation] > [Statut], type [Tous] pour voir les élèves sans protocole). Chaque enseignant et le chef d'établissement peuvent générer le fichier d'export ; comme les protocoles sont rattachés aux noms de groupes, chaque élève reçoit automatiquement son protocole dans Cyclades.
Élèves listés « ne sont dans aucun groupe d'examen et ne seront donc pas exportés » : s'ils n'existent pas dans Cyclades, l'alerte peut être ignorée ; s'ils y existent, les affecter à leur protocole avant d'exporter.
À ne pas faire : importer les élèves dans Cyclades depuis le logiciel de vie scolaire (Pronote, Notabene…) quand on utilise iPackEPS. Le document officiel le dit « à proscrire » : si les noms de groupes diffèrent de ceux d'iPackEPS, les élèves ne correspondent plus à leurs protocoles et il faut les replacer à la main dans Cyclades.
Établissements sans élèves dans iPackEPS (CFA, AEFE, certains privés) : ignorer le placement et l'export ; les élèves inscrits apparaissent dans Cyclades / Santorin, où l'équipe les place manuellement dans leurs protocoles (fiche partie 2).
Nature de la source : documentation officielle de l'application (assistance iPackEPS, académie de Créteil, conceptrice), version minimale 2026.2.x ; les dates et la validation par la commission relèvent du calendrier de l'académie.
Source : « Interfaçage iPackEPS / Cyclades, partie 1 : les saisies sur iPackEPS », 2026-2027, article 61 : https://ipackeps.ac-creteil.fr/spip.php?article61 (PDF lu le 3 novembre 2026).
